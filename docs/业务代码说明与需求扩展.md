## 二、已实现的核心业务规则

### 2.1 计时器式打卡（`IBizWorkLogService`）

| 环节 | 规则 |
|---|---|
| 开始打点 | ① 先查当前用户是否已有进行中计时器：`autoSwitch=true` 时自动结算上一条，否则抛业务异常提示先结束；② Redis 置标记 `biz:worklog:running:{userId}`（TTL 12h）；③ 数据库唯一索引 `uk_running_user` 兜底并发重复点击 |
| 结束打点 | ① 校验记录属主（本人或管理员）与状态；② **`UPDATE` 语句的 WHERE 强制带 `user_id` 且 `log_status='0'`**，防越权与重复结束；③ 时长由服务端 `end_time - start_time` 计算，**不信任前端上报**；④ 超 12 小时自动按上限截断并写备注 |
| 手动补录 | ① 不允许未来日期；② 只允许回溯 31 天内；③ 传了起止时间按时间差算，否则按小时数换算；④ 单条上限 24 小时；⑤ **当日累计不得超过 24 小时**（防把 20 小时误录成 200 小时） |
| 跨零点 | 自动按自然日切分为多条记录，首条结束原记录、后续插入新记录并标注「跨天自动拆分自记录 #id」，保证按天统计不失真 |
| 校验 | 项目必须存在且未归档；非项目成员不可打卡；任务必须属于所选项目且未被取消 |

### 2.2 收支记账（`IBizFinanceService`）

- **金额恒为正数**，方向由 `recordType`（0 收入 / 1 支出）决定；净额统一为 `SUM(CASE WHEN record_type='0' THEN amount ELSE -amount END)`。
- **类别方向一致性校验**：支出流水不允许选收入类别，反之亦然（否则报表会同时出现在两侧）。
- **流水号幂等**：`BK + yyyyMMdd + 4 位序号`，生成前查重，插入命中唯一索引时换号重试。
- **结算管理**：`settleRecord` 接收「本次结算金额」由服务端累加，自动推导结算状态（未结算 / 部分结算 / 已结清），并禁止累计超过流水金额。
- **类别保护**：系统预置类别（`sys_default='Y'`）、有子类别、已被流水引用的类别均禁止删除，只能停用。

### 2.3 统计核算（`IBizStatService`）

统一口径（代码与文档一致）：

```
工时统计   = WHERE del_flag='0' AND log_status='1'，按 log_date 归属（不用 start_time）
毛利       = 收入 - 直接成本
人力成本   = 工时 × 时薪（成员时薪优先，其次项目默认时薪）
净利润     = 毛利 - 人力成本
应收       = 收入 - 已结算金额
预算使用率 = 直接成本 / 预算
```

`selectProjectProfit` 用一条 SQL 把「项目 + 收支聚合 + 工时聚合」打平，派生指标在 Java 层补算，避免在 SQL 里堆 CASE WHEN 降低可读性。

### 2.4 微信小程序登录（`IBizUserWxService`）

- `code` → `jscode2session` 换 `openid`（封装在 `getOpenidByCode`，出错时抛出微信原始 `errmsg`）。
- 命中绑定：校验账号未被删除且未停用，刷新昵称/头像与最近登录时间。
- 未命中：按 `wx.miniapp.auto-register` 决定自动建档（`wx_` + openid 后缀，随机密码，默认部门取自 `wx.miniapp.default-dept-id`）或提示先绑定。
- **复用 RuoYi 令牌体系**：签发标准 JWT，小程序端 token 与 PC 端等价，可直接访问带 `@PreAuthorize` 的接口。
- 未配置 `appid/secret` 时进入**本地调试模式**（`dev_` + code 作为伪 openid），方便前端先跑通链路，生产环境必须配置密钥。

### 2.5 权限与数据隔离

- 后台接口：`@PreAuthorize("@ss.hasPermi('biz:xxx:yyy')")` + `@Log` 操作留痛，权限标识与 `sys_menu` 初始化数据一一对应。
- 数据权限：Service 方法加 `@DataScope(deptAlias="w"/"p"/"f")`，XML 末尾 `${params.dataScope}`，直接复用 RuoYi 的部门数据范围。
- 小程序接口：**不依赖角色权限**，在 Controller 层强制 `query.setUserId(getUserId())`，并在 Service 层校验记录属主，确保只能看/改自己的数据。

### 2.6 审计与删除

- **作废（log_status='2'）** 与 **逻辑删除（del_flag='2'）** 分离：前者是业务行为（工时填错），后者是管理行为（记录误建）。
- 所有统计只认 `del_flag='0' AND log_status='1'`，作废记录保留可恢复（`restoreWorkLog`）。

## 三、需求扩展清单

### 3.1 本次已在代码中落地的扩展

| # | 扩展需求 | 落地位置 |
|---|---|---|
| 1 | **一人同时仅一个进行中计时器**的双重保障（Redis 拦截 + MySQL 生成列唯一索引） | `startTimer` + `uk_running_user` |
| 2 | **跨零点自动按天拆分**，解决夜班/加班工时归属失真的经典问题 | `splitByDay` + `doFinish` |
| 3 | **忘记结束的兜底**：单次上限截断 + 每 30 分钟定时清理僵尸计时器 | `cleanOvertimeTimer` + `BizScheduledTask` |
| 4 | **手动补录风控**：不可补未来、限回溯 31 天、单条 ≤24h、单日累计 ≤24h | `addManualLog` |
| 5 | **项目成员与时薪**：把工时折算成人力成本，项目利润不再只算「硬件与服务开销」 | `biz_project_member` + `ProjectProfitVO.laborCost` |
| 6 | **项目盈亏驾驶舱**：毛利/毛利率/净利/净利率/应收/预算使用率/超预算标记 | `BizStatServiceImpl.enrich` |
| 7 | **应收应付（部分结算）**：支持预付款 + 尾款的分次收款，输出待收款合计 | `settleRecord` + `selectReceivableTotal` |
| 8 | **任务工时自动回写**：`biz_task.actual_hours` 由打卡记录汇总，列表页无需实时聚合 | `syncActualHours` 系列 |
| 9 | **微信侧账号体系**：独立 `biz_user_wx` 表，不改动 `sys_user`，支持一人多小程序 | `BizUserWxServiceImpl` |
| 10 | **小程序首屏概览**：今日/本周/本月工时、本月收支、待收款、近 7 天趋势、进行中计时器 | `dashboard` |
| 11 | **业务风控校验**：类别方向一致性、当日工时上限、结算金额上限、项目删除前置校验 | 各 ServiceImpl |
| 12 | **本地调试模式**：未配微信密钥也能联调登录链路 | `getOpenidByCode` |

## 四、部署与联调步骤

1. **建表**：在 `book_keep` 库执行 `sql/book_keep_biz.sql`（含 7 张业务表 + 字典 + 类别 + 菜单 + 定时任务）。
2. **编译**：在项目根执行 `mvn clean install`（新增了 `ruoyi-biz` 模块，需整体构建一次）。
3. **配置**：在 `application.yml` 的 `wx.miniapp` 下填入小程序 `appid` / `secret`；不填则进入调试模式。
4. **初始化**：把菜单 `记账管理`（menu_id=2000）授权给对应角色；单机自用可直接用 `admin`。
5. **定时任务**：确认 `sys_job` 中的「清理超时计时器」「回写任务实际工时」为启用状态（脚本已插入，状态=正常）。
6. **联调顺序建议**：
   `POST /wx/auth/login` 拿 token → `GET /wx/project/list` 选项目 → `POST /wx/worklog/start` 开始 → `POST /wx/worklog/stop` 结束 → `GET /wx/project/dashboard` 看概览。

## 六、已知约束

1. 项目下拉（`/biz/project/options`、`/wx/project/list`）未加部门数据权限过滤，团队场景下会看到全部进行中项目；如需收紧，可改为「我负责 / 我参与」两段查询。
2. `biz_work_log.running_user` 是 MySQL 生成列，**请勿在业务代码中写入该字段**；迁移到非 MySQL 数据库时需改用其他并发控制手段。
3. `mvn` 编译需 JDK 17（本机若默认 JDK 8，请先切换 `JAVA_HOME`）。
