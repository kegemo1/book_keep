bookkeepingWhiz · 数据库表结构设计说明

个人工时 / 任务打卡 + 项目收支记账系统 —— 在 RuoYi 自带系统表之上扩展业务库

基础框架：RuoYi 3.9.2（前后端分离） Spring Boot 4.1.0 / Java 17 / MyBatis MySQL 8.x · 库名 book_keep 字符集 utf8mb4 建表脚本：sql/book_keep_biz.sql

一、设计目标与总体思路

在完全不修改 RuoYi 自带系统表的前提下，新增 biz_ 前缀业务表，通过 user_id / dept_id / create_by 等字段与 sys_user、sys_dept、sys_dict_*、sys_menu 建立关联，从而直接复用 RuoYi 的登录鉴权、角色权限、数据权限（部门过滤）、字典与代码生成能力。

7业务表（6 必备 + 1 小程序可选）
3 级项目 → 任务 → 打卡 的归集层次
2 类打卡方式：计时器 / 手动补录
8 组字典类型（复用 sys_dict_data）

三条主线

  • 工时打卡：biz_project → biz_task → biz_work_log。一条打卡记录 = 某用户在某项目/任务上的一段时长；计时器与手动补录共用一张表，靠 log_type 区分。
  • 收支记账：biz_finance_category（类别树）+ biz_finance_record（流水）。金额恒为正数，方向由 record_type（0收入 / 1支出）决定，project_id 让每笔收支落到项目上。
  • 数据关联：所有业务表都带 user_id 与冗余 dept_id，既能按人统计，也能直接接入 RuoYi 的部门数据权限。
与 RuoYi 约定保持一致：继承 BaseEntity（create_by / create_time / update_by / update_time / remark）；逻辑删除统一 del_flag CHAR(1)（0存在 2删除）；create_by 存 sys_user.user_name 字符串而非用户 ID；不建物理外键（RuoYi 官方表同样如此），关联由应用层 + 索引保证。

  • idx_task_parent(parent_id) —— 子任务加载

4.3 biz_work_log　工时打卡记录表 核心表

用途：同一张表承载两种录入方式，避免统计时 UNION 两张表：

  • 计时器（log_type='0'）：点「开始」写一条 log_status='0' 的记录（只有 start_time）；点「结束」回填 end_time、duration，置 log_status='1'。
  • 手动补录（log_type='1'）：直接写一条 log_status='1'，start_time/end_time 可为空，duration 必填（例如「今天花 2 小时在 A 项目」→ duration = 7200）。
字段名类型允许空默认值说明
log_id PKBIGINT(20) AUTO_INCREMENT否—打卡记录主键
user_id FKBIGINT(20)否—记录人 → sys_user.user_id；小程序端从登录态取 SecurityUtils.getUserId()
dept_id FKBIGINT(20)是NULL冗余部门 ID，供 @DataScope(deptAlias="w") 直接过滤，避免 JOIN sys_user
project_id FKBIGINT(20)是NULL项目 → biz_project.project_id（NULL = 内部事务/未归类工时）
task_id FKBIGINT(20)是NULL任务 → biz_task.task_id
log_dateDATE否—归属日期（业务日期）。跨零点打卡时按业务规则归属，所有按天/按月统计都走它而不是 start_time
start_timeDATETIME是NULL开始时间：计时器必填；手动补录可空
end_timeDATETIME是NULL结束时间：进行中为空
durationINT(11)否0时长（秒）。计时器结束时 = end_time − start_time；手动补录直接填。展示层除 3600 得小时
log_typeCHAR(1)是'0'录入方式，字典 biz_work_log_type（0计时器 1手动补录）
log_statusCHAR(1)是'1'状态（0进行中 1已完成 2已作废）
billableCHAR(1)是'0'是否计费工时（0计费 1不计费），影响结算工时与收入核算
contentVARCHAR(500)是''工作内容描述
sourceCHAR(1)是'0'来源（0 PC 端 1 微信小程序），用于区分入口与埋点
running_user UKVARCHAR(32) GENERATED ALWAYS AS (...) VIRTUAL是—生成列：IF(log_status='0', CAST(user_id AS CHAR), NULL)，配合唯一索引在数据库层兜底「一人同时只有一个进行中计时器」
del_flag / BaseEntity 5 字段—是'0'同项目表

索引

  • UK uk_running_user(running_user) —— 计时器并发唯一性（Redis 做第一道锁，这里是最后一道防线）
  • idx_wl_user_date(user_id, log_date) —— 「我的工时」按日期区间查询，覆盖度最高的索引
  • idx_wl_project_date(project_id, log_date) —— 项目工时统计（按项目+时间范围）
  • idx_wl_task(task_id)、idx_wl_status(log_status, user_id)、idx_wl_dept(dept_id)
状态机约定：0进行中 → 1已完成（正常流程）；0/1 → 2已作废（作废保留审计痕迹，不物理删除）。作废与逻辑删除的区别：作废是业务行为（工时填错了），del_flag 是管理行为（记录误建），统计一律过滤 del_flag='0' AND log_status='1'。

4.4 biz_finance_category　收支类别表

用途：收入与支出的分类树（与 sys_dept 同构的父子结构）。支出侧覆盖「硬件设备 / 云服务 / 软件订阅 / 外包人力 / 差旅 / 推广」等成本科目，收入侧覆盖「项目收款 / 预付款 / 尾款」。sys_default='Y' 的系统预置项禁止删除。

字段名类型允许空默认值说明
category_id PKBIGINT(20) AUTO_INCREMENT否—类别主键
parent_id FKBIGINT(20)是0父类别 → 本表 category_id，0 = 顶级
ancestorsVARCHAR(500)是''祖级列表
category_nameVARCHAR(50)否—类别名称
category_typeCHAR(1)否—适用方向（0收入 1支出），保证收入/支出各维护一棵树
sys_defaultCHAR(1)是'N'是否系统预置（Y/N），预置项禁止删除以避免历史流水失去类别
order_num / status / del_flag / BaseEntity 5 字段—是—同项目表

索引

  • idx_fc_type(category_type, status) —— 记账页按收入/支出方向加载类别下拉
  • idx_fc_parent(parent_id) —— 树形加载

4.5 biz_finance_record　收支流水表 核心表

用途：记录每个项目的收入（收款金额）与成本投入（硬件/服务等）。金额恒存正数，方向由 record_type 决定，于是任一维度的净额都能写成统一的 SUM(CASE WHEN record_type='0' THEN amount ELSE -amount END)，无需维护两套表。

字段名类型允许空默认值说明
record_id PKBIGINT(20) AUTO_INCREMENT否—流水主键
record_no UKVARCHAR(64)否—流水号（如 BK20261008001），唯一，用于幂等与对账
user_id FKBIGINT(20)否—记账人 → sys_user.user_id
dept_id FKBIGINT(20)是NULL冗余部门 ID，供数据权限过滤
project_id FKBIGINT(20)是NULL项目 → biz_project.project_id（NULL = 公司公共开支）
task_id FKBIGINT(20)是NULL任务 → biz_task.task_id，可把成本精确归集到任务
category_id FKBIGINT(20)是NULL收支类别 → biz_finance_category.category_id
record_typeCHAR(1)否'0'收支类型，字典 biz_record_type（0收入 1支出）
amountDECIMAL(12,2)否0.00金额（元），恒为正数。上限约 99 亿，满足个人/小团队场景
tax_amountDECIMAL(12,2)是0.00税额（元）
currencyCHAR(3)是'CNY'币种（ISO 4217），为跨币种外包预留
record_dateDATE否—发生日期（统计维度；与 create_time 的区别：补记账时两者不同）
pay_methodCHAR(1)是'0'结算方式，字典 biz_pay_method（0微信 1支付宝 2银行 3现金 4其他）

settled_amountDECIMAL(12,2)是0.00已结算金额，支持分期收付款场景（应收/应付管理）
trade_noVARCHAR(64)是NULL第三方交易号/支付流水号（微信支付单号等），对账用
counterpartyVARCHAR(100)是''往来对象（客户 / 供应商 / 平台）
invoice_noVARCHAR(64)是''发票号
voucher_urlVARCHAR(500)是''凭证图片地址（小程序拍照上传后回填 CommonController 返回的 URL）
sourceCHAR(1)是'0'来源（0 PC 端 1 微信小程序）
del_flag / BaseEntity 5 字段—是'0'同项目表

索引

  • UK uk_record_no(record_no) —— 流水号唯一，接口重试幂等
  • idx_fr_user_date(user_id, record_date) —— 「我的账单」按日期区间查询
  • idx_fr_project_date(project_id, record_date) —— 项目盈亏测算的主力索引（WHERE project_id + 日期范围）
  • idx_fr_type_date(record_type, record_date) —— 收支方向 + 时间段的汇总/报表
  • idx_fr_category(category_id)、idx_fr_trade_no(trade_no)、idx_fr_dept(dept_id)

数据权限落地示例（工时打卡列表）

<!-- BizWorkLogMapper.xml -->
<sql id="selectWorkLogVo">
  select w.log_id, w.user_id, w.project_id, w.task_id, w.log_date, w.start_time,
         w.end_time, w.duration, w.log_type, w.log_status, w.content,
         p.project_name, t.task_name, u.nick_name as user_name
  from biz_work_log w
  left join biz_project p on p.project_id = w.project_id and p.del_flag = '0'
  left join biz_task    t on t.task_id    = w.task_id    and t.del_flag = '0'
  left join sys_user    u on u.user_id    = w.user_id
</sql>

<select id="selectWorkLogList" resultMap="BizWorkLogResult">
  <include refid="selectWorkLogVo"/>
  <where>
    w.del_flag = '0'
    <if test="userId != null"> and w.user_id = #{userId} </if>
    <if test="projectId != null"> and w.project_id = #{projectId} </if>
    <if test="params.beginLogDate != null and params.beginLogDate != ''">
      and w.log_date >= #{params.beginLogDate}
    </if>
    <if test="params.endLogDate != null and params.endLogDate != ''">
      and w.log_date <= #{params.endLogDate}
    </if>
    <!-- 部门数据权限：Service 层通过 @DataScope(deptAlias = "w") 注入 -->
    ${params.dataScope}
  </where>
  order by w.log_date desc, w.start_time desc
</select>

5.4 其他 RuoYi 能力对接

  • 代码生成器（ruoyi-generator）：导入 biz_* 表后，把生成模板的「编辑」列去掉 user_id / dept_id / del_flag，其余字段按 biz_ 前缀生成 Controller/Service/Mapper 与 Vue 页面，命名空间自动为 biz:project:* 风格。
  • 定时任务（ruoyi-quartz）：建议加两个 job —— ① 每天 00:05 把 log_status='0' 且 start_time 超过 12 小时的僵尸计时器自动结束；② 每天凌晨回写 biz_task.actual_hours。
  • 操作日志（sys_oper_log）：Controller 方法加 @Log(title = "工时打卡", businessType = BusinessType.INSERT)，打卡与记账这类敏感操作自动留痕。
  • 文件上传：收支凭证走 RuoYi CommonController#uploadFile，返回 URL 存入 voucher_url。
  • 导出（POI）：实体字段加 @Excel(name = "时长(小时)")；duration 建议在 Service 层转换为小时后再导出。

六、关键业务约束与应用层要点

6.1 计时器「开始 / 结束」的落库流程

动作数据库操作应用层校验
开始打点 INSERT biz_work_log (user_id, dept_id, project_id, task_id, log_date, start_time, duration=0, log_type='0', log_status='0') ① 先查 Redis worklog:running:{userId}，存在则直接复用；② 唯一索引 uk_running_user 兜底并发的重复插入
结束打点 UPDATE biz_work_log SET end_time=?, duration=?, log_status='1', update_by=?, update_time=? WHERE log_id=? AND log_status='0' AND user_id=? ① WHERE 必须带 user_id，防止越权结束他人计时器；② duration = TIMESTAMPDIFF(SECOND, start_time, end_time)，跨零点按规则切分（可按 24:00 拆成两条）；③ 若 duration < 60 秒，提示用户确认是否误点
手动补录 INSERT ... (log_type='1', log_status='1', duration=7200, log_date='2026-10-08') 时长必填且 > 0；log_date 默认当天，禁止补录未来日期；同一项目同一天可多条累加

6.2 「一人同时仅一个进行中计时器」的数据库兜底

-- 生成列：仅当 log_status='0' 时值为 user_id，其余为 NULL（NULL 不参与唯一约束）
running_user VARCHAR(32) GENERATED ALWAYS AS (IF(log_status = '0', CAST(user_id AS CHAR), NULL)) VIRTUAL,
UNIQUE KEY uk_running_user (running_user)

MySQL 中多个 NULL 不冲突，因此历史记录可以无限多，但「进行中」的记录每人最多一条。Redis 承担第一道拦截（性能），唯一索引承担最后一道（正确性）。

6.3 三个必须守住的统计口径

  • 工时统计：一律 WHERE del_flag='0' AND log_status='1'，且按 log_date 而非 start_time 过滤，避免跨零点记录漏统计。
  • 金额统计：SUM(CASE WHEN record_type='0' THEN amount ELSE -amount END) 得净额；只看收入/成本时分别加 record_type 条件，amount 永远是正数。
  • 项目盈亏：收入 − 直接成本 = 毛利；再减去「工时 × 时薪」得人力成本后的净值，才是真实利润。工时成本建议做成计算列而非落库，避免数据双写不一致。
-- 项目盈亏 + 工时成本一屏出结果
SELECT p.project_id, p.project_name,
       IFNULL(SUM(CASE WHEN f.record_type = '0' THEN f.amount END), 0)                          AS income_total,
       IFNULL(SUM(CASE WHEN f.record_type = '1' THEN f.amount END), 0)                          AS cost_total,
       ROUND(IFNULL(wl.hours, 0), 2)                                                            AS work_hours,
       ROUND(IFNULL(wl.hours, 0) * p.hour_rate, 2)                                              AS labor_cost,
       IFNULL(SUM(CASE WHEN f.record_type = '0' THEN f.amount ELSE -f.amount END), 0)
         - ROUND(IFNULL(wl.hours, 0) * p.hour_rate, 2)                                          AS net_profit
FROM biz_project p
LEFT JOIN biz_finance_record f ON f.project_id = p.project_id AND f.del_flag = '0'
LEFT JOIN (SELECT project_id, SUM(duration) / 3600 AS hours
           FROM biz_work_log WHERE del_flag = '0' AND log_status = '1'
           GROUP BY project_id) wl ON wl.project_id = p.project_id
WHERE p.del_flag = '0'
GROUP BY p.project_id, p.project_name, p.hour_rate;
