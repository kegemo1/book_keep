# 账时记 · 需求文档（Roadmap）

> 版本：v1.0　|　编写日期：2026-10-14　|　状态：待评审
>
> 定位：面向自由职业者/独立开发者的**工时打卡 + 项目收支核算**个人工具  
> 原则：单人闭环优先、数据归属清晰（微信独立身份）、每期只做一个主题

---

## 一、现状盘点（v1.0 已上线能力）

| 模块  | 已有能力                                            |
| --- | ----------------------------------------------- |
| 身份  | 微信一键登录、头像昵称、独立微信用户体系（biz_wx_user，与后台分离）         |
| 工时  | 秒表计时（跨天自动拆分）、手动补录、记录列表/作废、单日 ≤24h 校验、12h 超时自动收尾 |
| 任务  | 项目下二级维度：增删改查、完成/重开、进度、优先级、实际工时自动回写              |
| 项目  | 增删改、盈亏核算（收入/直接成本/人力成本/毛利/净利/应收/预算使用率）           |
| 记账  | 收入/支出、类别、结算方式、已结算、往来对象、税额、交易单号、发票号、凭证图片         |
| 统计  | 今日/本周/本月/累计工时、本月收支、近 7 天趋势、分类统计、项目盈亏清单          |
| 管理端 | RuoYi 后台：项目/成员/任务/类别/流水管理、报表导出、微信用户管理           |

## 二、用户画像与设计原则

- **画像**：1~~3 人团队或独立接单者，同时进行 1~~5 个项目，按项目/小时计费，需要向客户或自己交代"时间花在哪、钱赚没赚"
- **原则**：
  1. 记录动作 ≤ 10 秒完成（不打断工作流）
  2. 一切数字可追溯（每笔统计能下钻到原始记录）
  3. 数据属于用户（可导出、可注销删除）
  4. 单人功能优先，协作功能只做数据基础不抢主线

## 五、详细需求

### REQ-001 账号注销（P0｜合规必备）

**背景**：微信审核与《个人信息保护法》要求，提供用户信息删除能力；不提供会被审核驳回。

**功能描述**：

1. 「我的」→「账号注销」入口
2. 二次确认页：展示注销后果（所有工时/流水/项目数据将被删除且不可恢复）
3. 校验：存在**未结束计时**时禁止注销；存在**未收款应收**时二次强提醒
4. 注销动作：逻辑删除 `biz_wx_user`（del_flag=2、openid 置空），业务数据 `user_id` 保留但用户档案脱敏；30 天后物理清理（定时任务）
5. 注销后重新登录视为新用户

**验收标准**：

- [ ] 有进行中计时时点击注销给出阻断提示
- [ ] 注销后该微信再登录，历史数据不可见
- [ ] 管理端可见已注销档案及注销时间

**技术要点**：新增 `/wx/auth/cancel` 接口（POST，需 token）；删除逻辑放 Service 层事务内。

---

### REQ-002 数据导出（P0｜用户信任）

**背景**：记账工具最大的用户焦虑是"数据被锁死"。可导出 = 可信。

**功能描述**：

1. 「我的」→「数据导出」
2. 导出范围可选：全部 / 本年 / 自定义起止
3. 导出内容：打卡记录（项目、任务、起止、时长、计费）、收支流水（类型、金额、类别、项目、凭证链接）
4. 生成 Excel（两个 Sheet）+ JSON 备份文件，上传至服务器后推送下载链接（或直接 `wx.downloadFile`）
5. 导出记录留痕（导出时间、范围），防止接口被滥用

**验收标准**：

- [ ] 导出文件可在 Excel 打开，中文无乱码
- [ ] 金额与项目页统计一致（对得上账）
- [ ] 无数据时给出友好提示

**技术要点**：后端用 EasyExcel 生成；文件放 `/profile/export/`；小程序 `wx.downloadFile` + `wx.openDocument`。

---

### REQ-003 图表可视化升级（P0｜体验）

**背景**：目前仅近 7 天简易条形图，数字密密麻麻，缺少一眼可读的趋势与结构。

**功能描述**：

1. 首页/工时页：近 30 天工时**折线图**（可切换 7/30 天）
2. 记账页：本月收支**环形图**（按类别占比，点击扇区下钻该类别流水）
3. 项目页：收入 vs 成本**对比条形图**
4. 技术选型：`echarts-for-weapp`（ec-canvas，按需引入折线/饼图两个组件控制包体积）或轻量 `wx-charts`
5. 图表数据接口：`/wx/stat/chart`（聚合返回，避免前端多次请求）

**验收标准**：

- [ ] 首屏图表渲染 < 300ms（数据缓存 + 骨架屏）
- [ ] 包体积增量 < 200KB（echarts 按需构建）
- [ ] 空数据时展示占位插画而非空白

---

### REQ-004 快捷记账（P1｜效率）

**背景**：记一笔要选 6+ 个字段，高频场景（打 车/外卖/耗材）成本太高。

**功能描述**：

1. 首页新增「快捷记账」九宫格：用户自定义 4~8 个**记账模板**（预设：类型/类别/项目/金额/备注）
2. 点模板 → 只需确认或改金额 → 保存（≤ 3 秒）
3. 记账页记忆上次选择：项目、类别、结算方式默认上次值
4. 金额输入支持简单算式（如 `12+8.5`）

**验收标准**：

- [ ] 模板记账 3 次点击内完成
- [ ] 模板支持长按删除/排序

---

### REQ-005 打卡提醒（P1｜留存）

**背景**：忘记结束计时（僵尸记录的根源）与忘记每日打卡是两大流失点。

**功能描述**：

1. 「我的」→「提醒设置」：可开启"每日打卡提醒"（固定时间，默认 21:00）
2. 实现方式：**一次性订阅消息**（个人主体可用）。用户开启时请求订阅授权；每次授权推送一次 → 设计为"打卡结束时顺便请求下一次授权"，形成闭环
3. 提醒内容："今天还没记录工时哦，1 秒补录一下？"
4. 计时超时提醒：开始计时时请求授权，超过 10 小时未结束推送"你的计时已超 10 小时，忘记结束了吗？"

**验收标准**：

- [ ] 用户拒绝授权不报错、不打扰（设置页展示引导文案）
- [ ] 服务端定时任务扫描并发送，不重复推送
- [ ] 点击消息跳转对应页面（打卡页/计时中页）

**技术要点**：`wx.requestSubscribeMessage` + 模板 ID 申请；后端 `bizTask` 扩展定时任务 + `subscribe_message` 发送表（记录授权次数）。

---

### REQ-006 回收站（P1｜数据安全）

**功能描述**：

1. 作废的打卡、删除的流水/任务进入回收站，保留 30 天
2. 「我的」→「回收站」：按类型分组展示，支持单条恢复、批量彻底删除
3. 回收站数据不计入统计（与现状一致）

**验收标准**：

- [ ] 恢复后统计数据立即恢复
- [ ] 30 天自动清理（定时任务），清理前不可见

---

### REQ-007 周报/月报（P0｜核心价值）

**背景**：用户记录的终极目的是"向客户交差"和"给自己复盘"。

**功能描述**：

1. 「工时」「记账」页顶部新增周期切换：日 / 周 / 月
2. **周报**（周一自动生成上周）：总工时、按项目分布、新增收入/支出、与上周环比
3. **月报**（次月 1 日生成）：完整版周报 + 净利润、应收汇总、最耗时任务 TOP5
4. 报告页可导出为**长图**（canvas 渲染）发给客户/存档
5. 报告数据快照落表 `biz_report_snapshot`（防止历史数据变更导致报告变化）

**验收标准**：

- [ ] 周一 9 点前可查看上周报告
- [ ] 报告数字与明细页逐条对得上
- [ ] 长图保存到相册成功

**技术要点**：快照生成放定时任务；canvas 2d 绘制（注意长图分片）。

---

### REQ-008 时薪分析（P1｜深度洞察）

**背景**：自由职业者的核心命题——"我到底每小时值多少钱"。

**功能描述**：

1. 每个项目的**实际时薪** = 项目收入 ÷ 有效工时（含固定费项目折算）
2. 榜单：项目实际时薪排序（发现高价值客户/低价值消耗）
3. 月度个人时薪趋势：月收入 ÷ 月工时
4. 支持"期望时薪"设置，低于期望的项目标红提醒

**验收标准**：

- [ ] 无收入项目时薪显示 0 且不参与除零报错
- [ ] 计费工时与总工时口径可切换

---

### REQ-009 应收账期与逾期提醒（P1｜现金流）

**功能描述**：

1. 收入流水增加「账期天数」字段（默认 30）
2. 「项目页/记账页」新增应收账龄视图：未收/逾期 1-30/31-60/60+
3. 到期前 3 天与逾期当天推送提醒（订阅消息，复用 REQ-005 通道）
4. 记录回款动作（关联流水，已结算金额累加）

**验收标准**：

- [ ] 应收合计与项目页应收一致
- [ ] 回款后自动更新 settle_status 与项目应收

---

### REQ-010 周期性记账（P1｜省心）

**功能描述**：

1. 模板：名称、金额、类别、项目、重复周期（每月 X 号 / 每周 X）、起止
2. 定时任务自动生成流水（`auto_generated=1` 标记）
3. 生成前推送确认（可选），避免重复扣款场景生成错误数据
4. 列表中自动流水可一键停用

**验收标准**：

- [ ] 每月 1 日 0:30 统一生成，不重复不遗漏（幂等：模板+月份唯一）
- [ ] 删除自动流水不影响模板

### REQ-011 年度报告（P2｜仪式感）

**功能描述**：仿"年度账单"：全年总工时/总收入、最忙月份、最赚钱项目、与上年对比、高光任务；长图分享。12 月下旬开放，数据基于快照表。

---

### REQ-012 客户档案管理（P1｜B 端延伸）

**功能描述**：

1. `biz_customer` 表：名称、联系方式、备注、默认结算方式/账期
2. 流水与项目的往来对象升级为**客户引用**（历史文本数据迁移脚本）
3. 客户维度统计：累计收入、应收、合作项目数、最近合作时间
4. 客户详情页：该客户所有项目与流水

---

### REQ-013 分享卡片（P2｜传播）

**功能描述**：工时/盈亏/周报页生成精美分享长图（品牌化模板：头像+名称+核心数字）；支持保存相册与 `onShareAppMessage` 自定义图。注意**金额可选择性脱敏**（用户勾选"隐藏金额"则显示 ✔ 达成状态）。

### REQ-014 目标管理（P2）

**功能描述**：设置月度工时目标（如 160h）与收入目标；首页顶部进度环；达成/落后趋势预测（按当前日均推算月末达成率）。

---

### REQ-015 团队协作（P2｜暂缓）

**背景**：v1.x 坚持单人闭环。协作等用户主动提出（"我想和合伙人共享项目"）再启动。  
**概要设计**：项目级共享（邀请成员加入项目，按角色分配读写权限）；打卡仍归属个人，项目聚合视图合并展示；`biz_project_member` 表已预留。**依赖备案完成与用户量验证**。

## 七、暂不做（明确边界）

- 微信支付 / 会员订阅收费（个人主体不可用；未来如需，升级企业主体）
- 多人实时协作编辑（复杂度高，需求存疑）
- 银行卡/账单自动导入（涉及敏感授权与爬取，风险高）
- 小程序内嵌 Web 文章系统（偏离工具定位）
